# 验证与贡献

## 结构检查

在仓库根目录执行：

```bash
python scripts/validate.py
```

脚本需要 Python 3.10+，只使用标准库，不联网、不修改文件。检查：

- 核心文件与三份参考指南存在。
- frontmatter 中的技能名、描述和目录关系。
- 本仓库使用的 Markdown 行内链接所指向的内部文件存在，且没有越出仓库。
- 技能参考指南可从主入口找到。
- 客户端元数据保留默认发现，并包含正确的调用名称。
- 文本中没有明显的私人绝对路径或常见凭据形态。

它不是完整 YAML/Markdown 解析器，不检查远程 URL 可用性、页内锚点、所有秘密格式或模型行为。新增复杂 YAML 时应使用相应解析器验证。若环境提供 `skill-creator` 的 `quick_validate.py`，还可按该技能当前说明执行正式格式校验；不要假设其他人的校验器安装在固定路径。

## 行为验收场景

在隔离的示例项目里验证，避免改动生产站点。可先用规则推演发现冲突；需要证明执行结果时，应让助手实际完成场景并检查输出。

| 场景输入 | 应观察到的行为 | 不应出现的行为 |
| --- | --- | --- |
| 修改标题及其概念 | 核对导航、无障碍名称、相邻说明与已有交付包 | 只改大标题，或无条件替换所有历史文本 |
| 明确只改一个位置 | 只修改该处，说明真正存在的关联矛盾 | 擅自扩大到整页 |
| 取消某模块视频 | 清理占位、待更新提示与关联承诺，保留有用静态内容 | 删除原始录屏，或保留相互矛盾的 FAQ |
| 根据圈注调整一张截图 | 检查关键区域、完整性和实际文字大小 | 重设计整站或把关键操作裁掉 |
| 整站价值审查 | 区分问题、适用对象、路径、默认产出和扩展配置 | 编造效果数据，把采集结果写成已验证业务效果 |
| 增强教程视频 | 目标清楚，复制与引用等证据可见，稳定运镜，导出后回看 | 用网页复杂控制面板代替剪辑，遮挡真实界面 |
| 修复普通视频播放器 | 验证播放、暂停、拖动与需要的速度控制 | 不必要重做视频，或堆重复控件 |
| 表单修改后复制或下载 | 输出与当前输入、当前用途一致 | 显示新输入却复制旧结果 |
| 子目录新增并保留旧站 | 实际路径验证；完整包或明确的增量包与合并说明 | 将仅有新增目录的包声称为完整站点 |
| 缺少配套技能 | 使用基础流程，说明无法执行的具体能力 | 假装运行不存在的工具或强制安装全部依赖 |
| 仅要求本地交付 | 提供本地文件和验证结果 | 自动迁移到托管平台或发布 |

## 如何记录证据

说明实际执行了哪些检查，以及环境与范围。截图只能证明选定时刻的显示；视频流畅度需要回看导出文件；哈希一致只能证明文件字节相同。不要将一种检查推断为另一种能力已通过。

修改规则后，选择与改动相关的场景复验。无需每次文案修正都完整运行所有网站、浏览器和媒体组合，也不要把规则措辞是否出现当成唯一测试标准。

## 提交改进

Issue 或 Pull Request 请包含：需求和范围、最小输入、实际行为、预期行为、建议改动及验证方式。使用匿名示例，保留能说明问题的结构即可，不提交真实客户资料或登录信息。

判断改动是否值得进入主工作流：它是否解决重复出现的问题？是否可迁移？能否只放在按需参考指南？是否会令局部任务不必要地扩张？优先最小、可解释的修正。
