# 使用示例

以下是可直接改写的任务提示词。将目标文件、页面区域和素材路径换成自己的内容；它们是方法示例，不是已完成的客户案例。

## 局部标题修改

```text
使用 $web-design-workflow，把“分步操作”改成“能力协同”。
检查指向这个区域的导航、无障碍名称和相邻说明是否仍然准确。
保留其他内容、现有样式和稳定锚点；已有交付包也更新到最终版本。
```

预期：围绕同一概念修改关联位置，不重新设计整页。若原文实际描述严格步骤，应先核对内容关系再调整说明。

## 新建方案介绍页

```text
使用 $web-design-workflow，在当前项目新建一页方案介绍。
受众是需要判断是否采用该方案的业务人员。
请说明解决什么问题、适用条件、两条可选路径、共同产出和下一步入口。
沿用项目 DESIGN.md；现有材料不足的事实不要编造。
使用已有技术栈，在本地实现并验证。
```

预期：根据访客要做的判断组织内容；有配套技能时结合视觉方向、实现与复核分工。

## 整页价值审查

```text
使用 $web-design-workflow，检查当前介绍页是否清楚说明了价值。
重点找出重复内容、模糊承诺、错误的执行顺序、缺少的前置条件和含糊入口。
本次直接修正文案与受影响的交互，保留品牌、原始报告和产品事实。
```

如果只要评审，将最后一句改为“本次只给出具体问题和修改建议，不编辑文件”。

## 图片与二维码

```text
使用 $web-design-workflow，把提供的操作截图和原始二维码放入指定模块。
截图要能看清关键区域；二维码略微放大，与旁边的预约入口协调。
检查背景、留白、实际显示尺寸及识别结果，明确说明做过哪些验证。
```

预期：按用途决定裁剪和完整显示；二维码作为原始图层保留。图片生成工具不能重新绘制二维码数据。

## 教程视频增强

```text
使用 $web-design-workflow，并按当前工程使用对应的视频技能。
增强这段教程录屏：先解释任务目标，再展示真实操作和结果。
复制按钮、引用入口和展开内容都必须清楚可见。
减少无目的缩放，添加帮助理解的标注与动画。
完成后回看导出视频，再嵌入网页；网页使用普通播放器。
```

预期：改进视频内部的信息表达，保留关键证据。检验播放、暂停、拖动及需要的倍速能力，避免额外堆叠控制面板。

## 取消视频计划

```text
使用 $web-design-workflow，取消这一模块的视频安排。
删除占位和“待更新”提示，检查 FAQ、材料说明中是否还有相关承诺。
保留已有静态教程和原始录屏文件。
```

预期：只清理受影响的关联内容；删除网页提示不等于删除原始资产。

## 子目录交付

```text
使用 $web-design-workflow，将这页整理为现有站点 /guide/ 下的新增内容。
维护本地源文件，检查图片、字体、视频、下载和直接访问后的刷新。
现有站点其他页面必须保留。
如果缺少完整站点，请交付明确标注的增量包和合并说明，不冒充完整部署包。
本次只打包，不发布。
```

预期：核对发布目录关系，生成并检查归档；确认源文件与包内最终版本一致。

## 给现有项目设为默认流程

可在项目已有 `AGENTS.md` 中合并以下约定，保留其他指令：

```markdown
网页设计和修改使用 web-design-workflow。
先读取目标网站适用的 DESIGN.md，保留现有身份与行为。
局部修改包含受影响的关联检查；整站重设计须属于明确任务范围。
按需调用当前环境中可用的配套设计与媒体技能。
```

这段项目约定不替代 skill 安装。多个网站共用仓库时，应明确各自的设计文档与目标目录。
