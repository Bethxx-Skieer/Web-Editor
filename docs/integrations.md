# 配套技能与工具

## 安装策略

先安装 `web-design-workflow` 并完成一个小任务，再按实际工作补充配套能力。本仓库不会一键安装所有工具，也不把“列出了某技能”视为“已调用该技能”。

下面是工作分工。上游来源用于进一步了解与安装；实际命令和入口应以当前上游文档及本机技能列表为准。不同版本可能改变目录、命令或附带程序。

## 核心设计角色

| 技能 | 在此工作流中的分工 | 来源 |
| --- | --- | --- |
| `frontend-design` | 根据主题、受众与使用场景确定排版、构图、视觉重点 | [Anthropic skills](https://github.com/anthropics/skills/tree/main/skills/frontend-design) |
| `impeccable` | 实现与精修：布局、文案、交互、响应式、可访问性 | [Impeccable](https://github.com/pbakaus/impeccable) |
| `hallmark` | 复核模板化结构、无意义装饰与缺乏主题特点的问题 | [Hallmark](https://github.com/Nutlope/hallmark) |

有配套技能时，先读实际入口，再选择当前任务需要的部分。它们仍遵循目标网站的 `DESIGN.md`。例如已经明确的配色不应被主题库替换；单个按钮问题不应触发整站重设计。

某些 Impeccable 版本有上下文加载程序。仅在安装版本要求时按它的入口运行，不在此仓库固定一条可能过时的命令。失败时使用该版本的回退方式，继续可完成的本地工作。

## 按需能力

| 能力 / 技能名称 | 触发场景 | 前提与回退 |
| --- | --- | --- |
| `imagegen` | 需要生成或编辑真实使用的位图素材 | 需要宿主提供对应工具；已有合适素材优先复用；无能力时明确缺失 |
| `shaders` | 交互反馈、图像处理、主视觉或转场确有帮助 | 使用项目框架；考虑 WebGPU 支持、性能与静态后备；参考 [官方指南](https://shaders.com/docs/guide) |
| `identity-skill` | 强参考驱动的个人网站或作品集 | 属于可对接的技能名称；本仓库未提供其公开安装源，不作为必需依赖 |
| `build-project-showcase` | 项目或技能案例的证据整理与展示 | 属于可对接的技能名称；本仓库未提供其公开安装源；缺失时按现有证据完成基础介绍 |
| HyperFrames / Remotion 对应技能 | 明确要求增强、剪辑或制作教程视频 | 需要实际工程与运行工具；沿用既有项目和用户指定工具，不强制迁移 |
| 浏览器工具 | 检查渲染、可用性和播放器 | 使用宿主允许的浏览器能力；缺失时说明未完成视觉或交互验证 |
| 项目构建与部署工具 | 构建、打包或已授权发布 | 使用项目已有脚本与选定平台；不凭空引入新的托管服务 |

`imagegen` 可能是系统技能，也可能有插件前缀；不能假定其他人的电脑存在作者的同一文件路径。视频同理：本工作流不内置视频引擎。

## 缺少依赖时怎样工作

基础路线仍可完成：定位目标 → 读取约定 → 执行授权修改 → 检查相关文案和交互 → 按可用工具验证 → 说明实际完成情况。

如果任务要求的最终结果依赖缺失工具，例如必须交付一个重新渲染的视频，应完成不依赖该工具的整理，再说明具体缺少什么。不能用静态示意替代实际视频而不说明，也不能把未执行的浏览器测试记为通过。

## 版本与许可证

这里的分工针对能力，不承诺任意版本都存在完全相同的命令。团队可以在自己的项目记录已验证的配套版本；本仓库暂未提供全组合兼容矩阵。
